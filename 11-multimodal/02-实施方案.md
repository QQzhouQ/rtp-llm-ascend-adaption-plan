# Ascend 多模态（Qwen3.5 / Qwen3-VL）实施方案

> 前置：调研报告（01-调研报告.md）
> 载体模型：Qwen3.5-35B-A3B（本地 /mnt/docker/weights/Qwen3.5-35B-A3B，多模态检查点）
> 基线分支：bugfix/qwen35-aclgraph（图模式 + MTP 已就绪）

## 0. 总体策略

**从后往前、逐环打通**（③注入 → ②ViT → ①预处理），每环独立可验证、可单独成 PR。
图模式零冲突：ViT 只在 prefill 出现，aclgraph 是 decode-only。

## Phase 1：mm 注入开门（预估 0.5 天）

**改动**
1. `models_py/model_desc/qwen3_next.py::word_embedding`：删除 `_IS_ASCEND` 早返回，
   走基线完整路径（`embed_tokens(input_ids, position_ids, token_type_ids, text_tokens_mask)`
   + injector）
2. 验证 `embed_tokens` 多模态签名在 NPU 上的执行（Embedding 模块的 position/type 处理，
   纯 torch）

**验证**（此时 is_multimodal 仍为 False，纯文本不回归）
- 0.6B / 35B 纯文本 greedy 逐字不变（注入路径空转）
- ceval 冒烟不回归

## Phase 2：ViT 加载与前向（预估 2-3 天，核心环节）

**改动**
1. `models/qwen3_next/qwen3_next.py::_parse_mm_config`：删除 `if is_ascend(): return` 门
2. `multimodal_mixins/qwen3_5_moe/qwen3_5_moe_mixin.py`：
   - 确认 `self.visual = Qwen3VLVisionModel._from_config(...)` 构建无 CUDA 假设
   - 设备放置：`.to(device)` 链路走 torch_npu（`self._device` 来自模块属性，天然正确）
   - 权重加载：W() 映射覆盖 vision 权重（qwen35 检查点带 `visual.*` 前缀）
3. 排查点（逐个过）：
   - SDPA/attention 在 torch_npu 的 dtype（bf16）行为
   - `pos_embed_interpolate`（若 Qwen3.5 ViT 有）参考 vLLM-Ascend 的 native 实现
   - vit dtype 与 LLM dtype 对齐（`_data_type`）

**验证**
- 单元级：手工构造 pixel_values/grid_thw 喂 `self.visual`，输出 shape/dtype 正确、无 NaN
- 数值级：同输入在 CPU 与 NPU 各跑一次 ViT，输出 allclose（bf16 容差）
- 集成级：`is_multimodal=True` 下服务可启动、纯文本请求正常（ViT 空转不崩）

## Phase 3：mm processor / 图片输入链路（预估 2-3 天）

**改动**
1. C++ ingress：`MMProcessorConfig` 解析路径在 Ascend 下的实际行为验证
   （`resolveAndLogMMProcessorKind` 逻辑设备无关，预期 LOCAL 直接成立）
2. VitConfig 默认值清理：`vit_trt / trt_cache_*`（TensorRT 系）确保不触发
3. 前端 → backend 的图片字段传递（`multimodal_inputs` 序列化）跑通
4. AutoProcessor 在服务进程内加载（preprocessor_config.json 随检查点）

**验证**
- API 发 base64/URL 图片 → 预处理器输出 pixel_values 进 ViT → 日志确认 mm_features 非空
- 组合请求（图+文）端到端出 token

## Phase 4：端到端精度与性能（预估 1-2 天）

1. **正确性**：
   - 图文问答目检（图表/OCR/物体描述类 10-20 例）
   - 与 vLLM-Ascend 同检查点同图输出对比（有本地仓可对照）
2. **精度基准**：图文 benchmark 冒烟（MMMU/DocVQA 小样本，evalscope 或手工）
3. **性能**：
   - 纯文本不回归（TPOT 对齐 15.6ms 基线）
   - 图文请求 TTFT（ViT 前向耗时占比）
   - 可选：ViT 前向 torchair/图捕获（vLLM-Ascend 有先例，非必须）
4. **稳定性**：并发图文混合 + 长视频帧（长视觉序列）压测

## 风险与回退

- 每个 Phase 独立开关（门只在前移，不删除代码，可回退）
- ViT 数值异常 → 回退 Phase 2 的门，服务回到纯文本
- C++ ingress 阻塞超预期 → 备选：先支持 URL 图片走 python 侧预处理旁路
  （绕过 C++ processor，mixin 直接收图，验证 ViT 主链路不被阻塞）
