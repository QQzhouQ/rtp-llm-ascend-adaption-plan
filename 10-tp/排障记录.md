# 多卡通信 Demo 排障记录

## 环境

- 硬件: 8 × Ascend950PR NPU (编号 0-7)
- 软件: CANN 9.2.0 + torch 2.10.0 + torch_npu 2.10.0 (Python 3.11)
- 目标: 在后 4 张卡 (物理 NPU 4,5,6,7) 上运行 Broadcast 等通信原语 demo

---

## 排障过程

### 1. 环境识别 — 不是 NVIDIA GPU

初始假设为 NVIDIA 环境，执行 `nvidia-smi` 失败 (command not found)。
执行 `npu-smi info` 成功，确认为 **昇腾 (Ascend)** 环境，8 张 NPU。

### 2. 定位 Python 与 torch_npu

系统有多个 Python：
- `/root/miniconda3/bin/python3` (Python 3.14) — 无 torch
- `/root/miniconda3/envs/rtp-env/bin/python` (Python 3.11) — 有 torch 2.9.0+cpu + torch_npu 2.9.0
- `/usr/local/python3.11.15/bin/python3.11` (Python 3.11) — 有 **torch 2.10.0 + torch_npu 2.10.0 + hccl**，最完整

最终选用 `/usr/local/python3.11.15/bin/python3.11`。

### 3. 首次运行 — HCCL 初始化失败

启动脚本使用 `ASCEND_RT_VISIBLE_DEVICES=4,5,6,7`，运行报错：

```
RuntimeError: create_config:../torch_npu/csrc/distributed/HCCLUtils.cpp:140
NPU function error: device error type 0, error code is 4
```

- `dist.init_process_group("hccl")` 本身返回成功
- 但首个集合通信操作 (`dist.all_reduce`) 时在 `create_config` 阶段失败
- 所有 rank (1/2/3) 均报相同错误

### 4. 排除拓扑问题 — 所有卡都失败

尝试不同卡组合：
- `DEV_OFFSET=4` (NPU 4,5) → 失败
- `DEV_OFFSET=0` (NPU 0,1) → 同样失败

说明不是特定卡的问题，而是环境配置问题。

### 5. 定位根因 — 拓扑文件缺失

开启详细日志并调用 `acl.get_recent_err_msg()` 获取底层错误：

```python
ASCEND_GLOBAL_LOG_LEVEL=0
msg = acl.get_recent_err_msg()
```

得到关键信息：

```
Config_Error_Ranktable(EI0014):
Value /usr/local/Ascend/driver/topo/950/atlas_350_3.json
for ranktable variable topo_file_path is invalid.
Expected value: valid path.
```

检查发现 `/usr/local/Ascend/driver/topo/950/` 目录**不存在**。

### 6. 从 Docker overlay 层恢复拓扑文件

拓扑文件在 Docker overlay 层中存在，但未挂载到当前容器的活动路径：

```bash
# 查找文件位置
find /mnt/docker/overlay2 -name "atlas_350_*.json" -path "*diff*"

# 存在于 overlay merged 层
ls /mnt/docker/overlay2/41a.../merged/usr/local/Ascend/driver/topo/950/
# atlas_350_1.json  atlas_350_2.json  atlas_350_3.json
# atlas_850_1.json  atlas_850_2.json  atlas_850_3.json
# atlas_950_1.json

# 拷贝到正确路径
mkdir -p /usr/local/Ascend/driver/topo/950
cp /mnt/docker/overlay2/41a.../merged/usr/local/Ascend/driver/topo/950/*.json \
   /usr/local/Ascend/driver/topo/950/
```

拓扑文件内容为 NPU 间的 P2P 连接拓扑 (UB/PCIe 链路信息)，HCCL 需要它来选择最优通信路径。

### 7. 修复后验证

2 进程探针测试通过：

```
[rank0] OK all_reduce=3.0
[rank1] OK all_reduce=3.0
```

4 进程完整 demo 全部 PASS：

```
[rank *] broadcast check: PASS
[rank *] all_reduce(SUM): 10 (expected 10) PASS
[rank *] all_gather: [1.0, 2.0, 3.0, 4.0] PASS
```

## 排障关键步骤总结

| 步骤 | 操作 | 发现 |
|------|------|------|
| 1 | `nvidia-smi` 失败 → `npu-smi info` | 确认是昇腾 NPU 环境 |
| 2 | 逐个检查 Python 环境 | 找到 torch_npu 2.10.0 |
| 3 | 首次运行 demo | HCCL `create_config` error code 4 |
| 4 | 换卡组合测试 | 排除特定卡故障 |
| 5 | `acl.get_recent_err_msg()` + 详细日志 | 拓扑文件路径无效 |
| 6 | 从 overlay 层拷贝 topo JSON | 恢复拓扑配置 |
| 7 | 重新运行 | 全部 PASS |

---

## 经验总结

1. **昇腾环境优先用 `acl.get_recent_err_msg()`** — torch_npu 抛出的 RuntimeError 只给 error code，底层 ACL 错误信息需主动调用 `acl.get_recent_err_msg()` 获取
2. **HCCL 依赖拓扑文件** — `/usr/local/Ascend/driver/topo/950/*.json` 描述 NPU 间物理链路，缺失会导致通信域初始化失败
3. **容器环境注意挂载完整性** — Docker 容器中 driver 目录的 topo 子目录可能未正确挂载，需从 overlay 层恢复
4. **`ASCEND_GLOBAL_LOG_LEVEL=0`** — 开启最详细日志，适合深度排障
5. **用探针脚本逐步缩小范围** — 先用最小 2 进程 + 最简 all_reduce 测试，确认 HCCL 可用后再跑完整 demo
